## Индексы в BoundedRingBuffer<T> (N = 4, 6 элементов)

В буфере хранятся массив _buffer длиной N, индекс чтения _head, индекс записи _tail и счетчик _count.

При добавлении элемента:
- элемент пишется в _buffer[_tail]
- _tail = (_tail + 1) % N
- если буфер уже полон (_count == N), сдвигается _head = (_head + 1) % N, иначе _count увеличивается на 1

При чтении i-го элемента индекс считается как (_head + i) % N.

Пример для N = 4 при добавлении 1, 2, 3, 4, 5, 6:
- старт: массив [_, _, _, _], head = 0, tail = 0, count = 0
- после 1: [1, _, _, _], head = 0, tail = 1, count = 1
- после 2: [1, 2, _, _], head = 0, tail = 2, count = 2
- после 3: [1, 2, 3, _], head = 0, tail = 3, count = 3
- после 4: [1, 2, 3, 4], head = 0, tail = 0, count = 4
- после 5: [5, 2, 3, 4], head = 1, tail = 1, count = 4 (перезаписан 1)
- после 6: [5, 6, 3, 4], head = 2, tail = 2, count = 4 (перезаписан 2)

В итоге в буфере остаются элементы 3, 4, 5, 6 (читаются по индексам 2, 3, 0, 1). Добавление работает за O(1), так как массив не сдвигается.

## Ключ дедупликации для ActivityItem

Для проверки дублей используется структура ActivityKey из четырех полей: Platform, RepositoryFullName, Type и ExternalId.

Одного ExternalId недостаточно, потому что в разных репозиториях и типах событий номера совпадают (например, Issue #15 и PR #15). Сравнение строк сделано без учета регистра.

Ключи хранятся в HashSet<ActivityKey>, в структуре переопределены Equals и GetHashCode. За счет хеш-таблицы проверка и добавление ключа работают в среднем за O(1), а не за O(n) как при переборе списка.
