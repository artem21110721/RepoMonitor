## Разделение Issue и PullRequest в Forgejo REST API v1

В Forgejo REST API v1 эндпоинт /api/v1/repos/{owner}/{repo}/issues по умолчанию возвращает и обычные задачи, и Pull Request, так как на уровне модели данных PR являются расширением Issue. Если забирать и /pulls, и /issues без фильтрации, каждый Pull Request попадет в ленту дважды.

В ForgejoPlatformClient разделение реализовано на двух уровнях:
1. На уровне запроса в URL передается параметр type=issues (/api/v1/repos/{owner}/{repo}/issues?state=all&type=issues&limit=5), чтобы сервер сразу исключил Pull Request из выборки.
2. На уровне разбора JSON в методе ParseIssues для каждого объекта дополнительно проверяется поле pull_request: если свойство присутствует и его ValueKind не равен JsonValueKind.Null, элемент пропускается.

Pull Request при этом запрашиваются отдельно через /api/v1/repos/{owner}/{repo}/pulls?state=all&limit=5 и сохраняются с типом ActivityType.PullRequest.
